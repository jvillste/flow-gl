Event handling
-------------
When awt event occurs, it is added to an event queue (persistent queue in a ref).

Application loop
- if the event queue is empty and no animations are running block
  until the event queue contains something
- update application state based on events from the event queue
- update application state based on elapsed time
- offer the render loop the new application state to be rendered using a SynchronousQueue
- wait for the next frame to achieve the requested frames per second

Render loop
- wait for a new application state to be rendered using a SynchronousQueue
- update gpu state based on the application state
- render

# Equalizing width of boxes on a vertical stack

Vertical stack with :fill-width?, equalized the box sizes, but we want
to equalize the widths of the first childs, which are the rectangles
wrapping the contents. Box with :fille-width? sets the rectangle
widths to available-width. That is too wide, since we want to set the
width to the widest box in the stack.

Setting the available-width to the width of the widest box in
vertical-stack is not possible, since the widths of the children are
not known when the available-widths of the children must be given.

Box should know it's final size before laying out it's children. If
box has boxes as children, they should know their final size before
laying out their children. Vertical stack needs to know the preferred
sizes of the children before setting their final size.

# two pass layout

parent adds child :x :y :width and :height and calls layout for it.


when vertical stack lays out it's children some of them might be the
same objects as when the layout was done previously. If they are laid
out as before, the previously laid out object should be preserved.

How can we make sure, that if a child is the same as on the last
layout round and it gets the same position, the same java object is
retained?

If some other child is changed, the parent is not the same and thus we
can't find the previous layout from the cache.

We find the previous node by path from the previous layout.

when measuring and layout was done on a single pass from bottom to
top, cacheing was trivial since layout of a node did not affect the
layout it's siblings and could thus be cached like the measuring can
be cached in two pass layout.

Because size of a node can affect the size of it's siblings, we must
first calculate the new layout and compare it to the previous one to
see if we could use the same java object as the final result. That is
what node-image-cache does.
